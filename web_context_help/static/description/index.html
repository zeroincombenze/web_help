Adds a |sos| button to the control panel of every view: it opens the help of the current view in a separate window, so the Odoo tab stays usable.

  • Help pages are written in RST by each module, in its help/ directory
  • The help window follows the navigation (Follow Odoo), highlights the fields named by the page and can start a guided tour
  • Questions are answered by a full-text search over the help sections; every question is logged for the administrator
  • Administrators can edit a page; the edited version survives the upgrades and a warning appears when the original source changes
  • A page can be chosen by a field of the open record, many2one included: by the :when: of its RST source or by rules set by the administrator, e.g. a different sale order help for each order type

Configuration | Configurazione

No configuration is needed. Pages are rebuilt at server start when a help source changes; a help editor can force it with Rebuild all pages in Help > Help Editor > Help Pages.

Every internal user reads the help. Who edits it is set in the user form (Settings > Users, field Context Help in the Other section):

  • empty: no edit, the help is only read;
  • User: edits the help pages of priority lower than 64 and their rules. Editing a page of priority 64 or more, e.g. a page of a module (96), creates a copy of it with the default priority (32), and the copy is edited: being of higher priority, it is shown in place of the original;
  • System: edits all the help pages, as before.

The field sets the level of the administrators too: they start as System (when the module is installed, or already had it before this version), and can be lowered to User or to no edit. A user made administrator later gets no help level by default.

Both levels need no administrator rights: opening the Help app, they get its Help Editor menu in the top bar (pages, rules, questions asked) and the Edit button of the help window.

The videos inserted in the help pages are read from the directory of the system parameter web_help_video_path (default ~/Video, the home of the user running Odoo), subdirectories included; change it in Settings > Technical > System Parameters.

Non serve configurazione. Le pagine sono ricostruite all'avvio del server quando cambia una sorgente di aiuto; un editor dell'aiuto può forzarlo con Ricostruisci tutte le pagine in Aiuto > Editor dell'aiuto > Pagine di aiuto.

Ogni utente interno legge l'aiuto. Chi lo modifica si imposta nella scheda utente (Impostazioni > Utenti, campo Aiuto contestuale nella sezione Altro):

  • vuoto: nessuna modifica, l'aiuto è solo letto;
  • Utente: modifica le pagine di aiuto con priorità minore di 64 e le loro regole. Modificando una pagina con priorità 64 o più, ad es. una pagina di un modulo (96), se ne crea una copia con la priorità predefinita (32) e si modifica la copia: avendo priorità più alta, è mostrata al posto dell'originale;
  • Sistema: modifica tutte le pagine di aiuto, come prima.

Il campo imposta anche il livello degli amministratori: partono come Sistema (all'installazione del modulo, o se lo avevano già prima di questa versione) e possono essere abbassati a Utente o a nessuna modifica. Un utente reso amministratore in seguito non ha un livello di aiuto predefinito.

Nessuno dei due livelli richiede diritti di amministratore: aprendo l'app Aiuto, hanno il suo menu Editor dell'aiuto nella barra in alto (pagine, regole, domande poste) e il pulsante Modifica della finestra di aiuto.

I video inseriti nelle pagine di aiuto sono letti dalla cartella del parametro di sistema web_help_video_path (predefinito ~/Video, la home dell'utente che esegue Odoo), sottocartelle comprese; si cambia in Impostazioni > Tecnico > Parametri di sistema.

Usage | Utilizzo

The Help menu, at the top of the menu tree, opens the help home page in the help window. The Summary button in the header lists, grouped by module, the pages of every installed help module; Ready goes back to the home page. Users allowed to change the help pages also see Edit, which opens the page in the backend: the home page itself can be adapted like any other page. In the editor, the film button of the floating toolbar (or the /Help video command) lists the videos of the video directory: the chosen one is inserted after the current paragraph, as a player started by a click. To remove a video, press Backspace in the line after it or Delete in the line before it. In developer mode the </> button shows the HTML code of the page.

Press the |sos| button in the control panel. Pages are looked up by view xmlid, then by model and view type, then by model; otherwise an automatic page lists the fields help.

The box in the help window header finds text in the page, like the browser Ctrl+F (which focuses it). Case and accents are ignored, line breaks and bold or linked words too. With several words, words of 1-2 letters are ignored and only the places where all of them are within 12 words in the same paragraph are shown; when there is no such place, every occurrence of every word is shown and the counter says any word. Text in quotes ("draft invoice") is searched as an exact phrase. Enter / ▼ and Shift+Enter / ▲ go to the next / previous match, Esc clears the search.

The Example and FAQ sections of a page and the fields help of its model are shown on their own pages, opened by the Example, FAQ and Fields buttons in the help window header; the Help button goes back to the page (on the Example, FAQ and Fields pages it is labelled Topic). The questions built by help-question :auto: are left to the Fields page.

Moving from page to page of the help window, the Topic button goes back to the help page of the view open in Odoo; it is hidden when that page (or its Example / FAQ / Fields page) is the one shown.

Writing help for a module: put RST files in help/common/ or in the directory of a group of Odoo versions (help/v10, help/v11_14, help/v15, help/v16_20); a group file overrides the common one with the same name. Italian twins are named page.it_IT.rst.

Standard layout: every page has these sections, in this order, with their label and title; some apply only to the form or only to the list view (a kanban view follows the list rules):

  • Contents: table of contents, built by the help window, not written in RST; it lists the sections left on the page, footer excepted; the sections of a page with several parts (titles of first level) are grouped by part
  • description Description: summary of the view / model; its first paragraph is always "Click on button `` Ready `` for help about how to use this help; click on button `` FAQ `` for the most common solved questions." (Italian: "Fare clic sul pulsante `` Pronto `` per sapere come usare questo aiuto; fare clic sul pulsante `` FAQ `` per le domande più comuni già risolte.")
  • new_record How to insert a new record: in the form, steps to insert a record; in list / kanban, a brief text about the New button (Create up to Odoo 15)
  • search Suggestions for search: list / kanban only, how to find, filter and group
  • update_record How to update a record: in the form, steps to update a record; in list / kanban, a brief text: click on a line (list) or on a card (kanban) to open its form
  • cancel How to cancel or delete record when the model has a state field, else How to archive or delete record: form and list, steps to cancel (or archive) a record, restore it and delete it, with the conditions that forbid each step
  • configure How to set up: settings and configuration
  • report Report and export file: prints, pdf attachment, export
  • example Example: useful examples, on their own page opened by the Example button
  • faq FAQ: help-question blocks, on their own page opened by the FAQ button; the first paragraph, before the first question, is always "Click on button `` Topic `` to return to the specific help page." (Italian: "Fare clic sul pulsante `` Argomento `` per tornare alla pagina di aiuto specifica.")
  • footer Footer: date and time of page creation and copyright notice, not in the table of contents

A section that does not apply keeps one line saying so.

.. help-question:: How do I add a tag?

Use the :field:`Tags <category_id>` field.

.. help-question:: :auto:

:when: shows the page only when the open record (its selection, boolean and many2one fields) or the menu (its default_<field> context keys) match: conditions field = value, field != value, several values joined by comma, several conditions joined by and. When the value is unknown the page is not used, e.g. move_type != entry keeps the invoice help away from the journal entries, which share the invoice form. A many2one value is the xmlid or the id of the record, e.g. type_id = sale_order_type.normal_sale_type; False means empty. Among the pages of the same priority that can be shown, the one meeting more conditions wins: a page with :when: beats the page without it.

Rules

Without writing RST, a help editor chooses which page is shown from Help ‣ Help Editor ‣ Help Rules or from the Rules tab of a page: field of the page model (selection, boolean or many2one), *is* or is not, and the values (selection), the checkbox (boolean) or the record (many2one). A page with rules is shown when one of them is met, and the :when: of its source too.

The rules apply to the Clear cut pages only: a clear cut page is shown only when one of its rules is met. Every page has a Priority, 1 being the highest. The clear cut pages are checked first, in priority order: the first one with a rule met is shown. With no rule met, the general page (not clear cut, its rules ignored) with the highest priority is shown. The pages of the administrator get 32 by default, the pages built from the modules 96: these are the last fallback, always available. The priority of a module page is set by the :priority: option of its help-page, 96 when missing.

A clear cut page, or a page of priority 64 or less, shows the Loose help button in the help window: it opens the general page of priority 64 or more with the highest priority, for the same record, usually the page of the module.

Example: sale orders with a different help for each OCA sale_order_type. Create a page per type (Help Pages ‣ New: key, title, model sale.order, view type form, content), check Clear cut and add to it the rule Type is <the type>. Orders of the other types keep the standard sale order help. A page created this way, or by Duplicate of the standard page (key followed by " (copy)"), has no source: it is kept by the rebuild of the pages.

:position: is one of before, after, replace, remove. :auto: builds the questions from the fields help of the page model.

A page shows only the text of the running Odoo version: put version specific blocks in help-version and version specific words in the :version: role; the version directories remain for whole files that differ.

.. help-version:: >=17

RST shown on Odoo 17 and later (sections allowed)

Press :version:`16|Create and View Invoice;17|Create Draft Invoice;>=18|Create Draft`.

Conditions: 16, 16-18, >=17, >17, <=16, <17, or a star (the star: any version), several joined by comma (10,16). The role shows the text of the first matching condition, inline markup allowed, roles not allowed; write \ before the role when it is glued to the previous word. Roles :field: and :tour: highlight a field or run a tour in the Odoo tab.

A button label written between [ and ] with backquotes, `` Save ``, is shown as a button, the label inside a frame. Inside :version: the backquotes are escaped: ``:version:`<16|[\`Create\`];>=16|[\`New\`]```. It cannot be nested in Italic and bold are written with one or two stars around the words (italic, bold); in a code block the stars stay as written. The help pages write every button this way; menu paths (``Sales ‣ Orders``), tabs, menu items after ‣ and titles stay in bold.

Text that makes sense only with another module goes in help-if: it is shown only when the module is installed, or the model exists. The pages are rebuilt when a module or model named by a condition is installed or removed, in whatever order the modules are installed.

.. help-if:: module = sale

Invoicing from sale order -------------------------

RST shown only when sale is installed (sections allowed)

.. help-if:: model = sale.order and module != purchase

RST shown when sale.order exists and purchase is not installed

Conditions: module or model, = (any of the names joined by comma is installed / exists) or != (none of them), several joined by and.

Guided tours

help-tour writes a guided tour in the page, where it is needed, e.g. in How to insert a new record. With the Context help tours module (web_context_help_tour) installed, the help window shows a button: pressed, it plays the steps in the Odoo tab, one at a time, dimming the screen around the element of the step, with the Previous, Next and Stop buttons. Without that module the tour is not shown. The steps are written in the page, so the Italian twin has its own text and help-version / help-if work inside the tour too.

.. help-tour:: res_partner_new :label: Show me how to create a contact

.. help-step:: new :click:

Press New to open an empty contact form.

.. help-step:: field:name :position: right

Type the name: it is the only required field.

:label: is the text of the button, Show me how when missing. Targets of help-step: field:<field name> (the field and its label; the column in a list), button:<button name>, ``tab:<notebook page name>, menu:<menu xmlid>, css:<selector>, or new, save``, discard, search, filters, actions (gear menu), breadcrumb, statusbar. :click:: Next presses the target for the user, e.g. New; :position: places the popover (auto, top, bottom, left, right). A step whose target is not on screen waits for it: the user opens the screen, or does what the previous step asks. The targets are those of the Odoo version: put the tour in a help-version block of the versions it was checked on.

Regole

Senza scrivere RST, un editor dell'aiuto sceglie quale pagina mostrare da Aiuto ‣ Editor dell'aiuto ‣ Regole di aiuto o dalla scheda Regole di una pagina: campo del modello della pagina (selezione, booleano o many2one), *è* o non è, e i valori (selezione), la casella (booleano) o il record (many2one). Una pagina con regole è mostrata quando una di esse è soddisfatta, e anche il :when: della sua sorgente.

Le regole valgono solo per le pagine Clear cut: una pagina clear cut è mostrata solo quando una delle sue regole è soddisfatta. Ogni pagina ha una Priorità, 1 è la più alta. Le pagine clear cut sono controllate per prime, in ordine di priorità: è mostrata la prima con una regola soddisfatta. Se nessuna regola è soddisfatta, è mostrata la pagina generale (non clear cut, le sue regole sono ignorate) con la priorità più alta. Le pagine dell'amministratore hanno 32 come predefinito, quelle costruite dai moduli 96: sono l'ultima alternativa, sempre disponibile. La priorità di una pagina di modulo è data dall'opzione :priority: del suo help-page, 96 se manca.

Una pagina clear cut, o di priorità 64 o inferiore, mostra nella finestra di aiuto il pulsante Aiuto generale: apre la pagina generale di priorità 64 o superiore con la priorità più alta, per lo stesso record, di solito la pagina del modulo.

Esempio: ordini di vendita con un aiuto diverso per ogni sale_order_type OCA. Creare una pagina per tipo (Pagine di aiuto ‣ Nuovo: chiave, titolo, modello sale.order, tipo vista form, contenuto), spuntare Clear cut e aggiungere la regola Tipo è <il tipo>. Gli ordini degli altri tipi mantengono l'aiuto standard dell'ordine di vendita. Una pagina creata così, o con Duplica della pagina standard (chiave seguita da " (copy)"), non ha sorgente: è conservata dalla ricostruzione delle pagine.

18.0.1.0.13 (2026-11-14)

  • [NEW] Guided tours: help-tour / help-step directives write the steps in the page, shown as a button by web_context_help_tour; the help window sends the steps to the Odoo tab and its find box skips them
  • [IMP] Tour button: while its tour plays it reads Return to record view and brings the Odoo tab back; the original label returns when the tour ends
  • [IMP] Standard layout: new section cancel, How to cancel or delete record (model with state) or How to archive or delete record, after How to update a record
  • [IMP] Standard layout: list and kanban pages have the sections How to insert a new record (brief: button New / Create) and How to update a record (brief: click on a line or a card)
  • [NEW] Button frames: [`Save`] in the RST shows the label as a button, inside a frame, in the help window and in the page editor
  • [QUA] Test coverage 95% (1316: 64+1252) [0 TestPoints] - quality rating 54 (target 100)
  • [IMP] Help home and help editor pages: buttons written [`Label`], shown inside a frame; the mandatory Ready / FAQ / Topic sentences use it too

18.0.1.0.12 (2026-11-08)

  • [FIX] Odoo tab loaded in the help window (expired session, login): the help pages no more replace the Odoo views, e.g. the Invoicing dashboard
  • [IMP] Help pages: the Help pages page starts with the hint to the Ready and FAQ buttons; every FAQ page starts with the hint to the Topic button; the rules are in USAGE
  • [IMP] Help on help: how to move inside the help, the header buttons, the FAQ, the find box; FAQ of the main page
  • [IMP] Help edit authorization in 3 levels, field Context Help of the user form, now in the Other section: empty (no edit), User (new: edits the pages of priority lower than 64; editing a page of priority 64 or more edits a copy of it with the default priority) and System (edits all the pages, the former Help Editor group); the administrators are no more System by default: the field sets their level too, the existing ones keep System

18.0.1.0.11 (2026-11-07)

  • [QUA] Test coverage 95% (1194: 60+1134) [0 TestPoints] - quality rating 54 (target 100)
  • [IMP] Help window: admonitions (.. important::, .. warning::, .. admonition::) shown as a highlighted box

18.0.1.0.10 (2026-11-01)

  • [IMP] Help window: the page starts with its table of contents (Indice in Italian), built from its sections, footer excepted
  • [IMP] Help window: new Example button (Esempio in Italian): the Example section is shown on its own page, like the FAQ
  • [IMP] Help window: Font Awesome icons on the header buttons: Topic (anchor), Ready (life saver), FAQ (question), Loose help (globe), Example (eye), Fields (map), Summary (table), Edit (edit)
  • [IMP] Help window: on the Example, FAQ and Fields pages the button back to the page is labelled Topic (Argomento in Italian), and the Loose help button is not shown
  • [QUA] Test coverage 95% (1135: 59+1076) [0 TestPoints] - quality rating 54 (target 100)
  • [IMP] Help window: new Topic button (Argomento in Italian), back to the help page of the current Odoo view after moving to other pages; hidden when that page, or its FAQ / Fields page, is shown

18.0.1.0.8 (2026-10-30)

  • [IMP] List pages no longer get the "Searching with the wildcard" text at the end of their How to search section: the wildcard search is explained once, in the "Ready help" part of the help home page
  • [FIX] Documentation: the Usage section is shown again in the module page (index.html)
  • [IMP] Help window: the Home button is renamed Ready (Pronto in Italian)
  • [IMP] Help home page: new part "Ready help", before "Help on help", with the chapters "Activate developer mode" (with picture), "Finding, filtering and grouping a list" (search bar picture, searching, searching several words, wildcard search, filters, groups, favorites, breadcrumbs, view switcher and pager) and "Import and Export data" (export, import, updating records by External ID)
  • [FIX] Page keys quoted in the URLs: a duplicated page (key ending with " (copy)") opens
  • [IMP] RST engine aligned with 10.0
  • [IMP] Help page of the Help pages form for Odoo 10 (help/v10), shared with 10.0

18.0.1.0.7 (2026-10-29)

  • [IMP] The Help Editor menus are in the Help app, no longer an app of their own: the Help app still opens the help window and, for the help editors, shows the Help Editor menu in the top bar

18.0.1.0.6 (2026-10-22)

  • [IMP] help-page :when: condition on many2one fields too, the record named by xmlid or id, e.g. type_id = sale_order_type.normal_sale_type
  • [IMP] Help rules (Settings ‣ Technical ‣ Context Help ‣ Help Rules, or the Rules tab of a page): the administrator chooses which page is shown by a selection, boolean or many2one field of the record, no RST source needed; several rules of a page are alternatives; in the rule form field, operator and value are shown together
  • [IMP] Help lookup by page Priority (1 the highest) and Clear cut flag: the clear cut pages come first, the first one with a rule met is shown; otherwise the general page (not clear cut, its rules ignored) with the highest priority: pages of the administrator (default 32) before the pages of the modules (96), the last fallback; same priority, the page meeting more :when: conditions wins
  • [IMP] Help pages created by the administrator are kept by the rebuild of the pages and their sections are built from their content
  • [IMP] Help Editor group: writes the help pages, their rules and reads the questions asked, with no administrator rights, from the new Help Editor app; the administrators are help editors too
  • [IMP] help-page :priority: option, the priority of a module page (96 when missing)
  • [IMP] Help window: Loose help button on a clear cut page or a page of priority 64 or less: opens the general page of priority 64 or more with the highest priority, for the same record (usually the page of the module)
  • [FIX] Odoo 18 form views: the help sees the fields of the open record (the form view did not share its record with the control panel), so the :when: conditions and the rules work on the record; the help window follows the record when it is saved or the pager moves to another one
  • [FIX] Help pages: Duplicate no longer fails on the duplicate key: the copy key ends with " (copy)" (" (copy 2)" and so on for further copies); the copy has no source file, so it is a page of the administrator kept by the rebuild

18.0.1.0.5 (2026-10-14)

  • [IMP] Help pages: Help video button in the floating toolbar of the editor (and /Help video command): inserts a video of the directory set by the system parameter web_help_video_path (default ~/Video), played on click; Backspace or Delete next to a video removes it
  • [UPD] Help pages: HTML code view (</>) shown only in developer mode, as in standard Odoo; the custom field widget is removed
  • [FIX] Help pages: the Sections of a page edited by the administrator (editor or HTML code view) are rebuilt from its content, so the added headings and text are listed and found by the search; a reset to source rebuilds them too

  • [IMP] Help window: Summary button, page listing the help pages of every installed help module, each title followed by its view type (list) or (form); Home and Edit buttons
  • [FIX] Help window: a malformed lang in the URL (e.g. ?lang=it_IT?debug=1) no longer falls back to the English page
